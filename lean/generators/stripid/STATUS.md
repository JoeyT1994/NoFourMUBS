# Strip square-sum identities (I4): status (15 Oct 2026)

## Proved, standard axioms only (`propext`, `Classical.choice`, `Quot.sound`)
- `NoFourMUBs.PRM.Coverage.zeroJAlgebra : ZeroJAlgebra` in `PRM/CoverageStripIdZero.lean`.
- `NoFourMUBs.PRM.Coverage.nonzeroJAlgebra : NonzeroJAlgebra` in `PRM/CoverageStripIdNonzero.lean`.
- Both are exported by `PRM/CoverageStripId.lean`. All modules built, and `#print axioms` was run on 15 Oct.
- `NoFourMUBs.lean` imports none of these files. `NoFourMUBs/Final.lean` (another agent's file) imports
  `CoverageStripIdZero`.

## Method
1. Row scaling `s = t = 1` (`CoverageStripIdFormal`: `fData`, `fData_mom_scale`, `momentPoly_scale`,
   `halves_scaled`).
2. The two halves become `QF` circuits in `(z | k, X, Y)` with `ζ = r s/t` (`CoverageStripIdQF`, `CoverageStripIdHalf`).
3. Kernel checks compare these circuits with reduced data generated by the scripts here.
4. The modulus relation `G = 0` enters through one explicit quotient polynomial: `q2C` in the zero case,
   `qC` (42,563 terms) in the nonzero case.
5. Nonzero `J` uses the dense test `Circ.validN` (`CoverageStripIdFast`): natural-number GMP evaluation
   at base `2^K + baseOff`. The odd offset avoids kernel cache blow-up when large values share their low bits.
   It also uses explicit list data (`hornerZ`) instead of packed codes.

## Memory and time (max RSS includes about 6 GB of Mathlib import)
- Elaboration is slow for the large data modules: DataN 526 s, DataQ 931 s, DataP1 499 s (each 7–9 GB).
- Over the 12 GB target:
  - `CheckS1`: 13.9 GB, 57 s.
  - `CheckSF`: 13.8 GB, 58 s.
- Below it:
  - `CheckQ` 11.2 GB.
  - `CheckSA` 9.5 GB.
  - All other checks are under 10 GB.
- A split version of the two oversized checks is prepared but not yet built, in `split/`:
  - `CheckS1a`/`CheckS1b` with the new data `DataP1a`.
  - `CheckSFa`/`CheckSFb` with the new data `DataPS`.
  - `CoverageStripIdNonzeroSum.split.lean` is the matching `Sum`.
- To switch to the split version:
  1. Move the `split/` files into `NoFourMUBs/PRM`, renaming `Sum.split` to `Sum`.
  2. Delete `CheckS1` and `CheckSF`.
  3. Build DataP1a, DataPS, CheckS1a, CheckS1b, CheckSFa, CheckSFb, NonzeroSum, Nonzero, CoverageStripId.
  4. Re-run `#print axioms`.

## Regenerating data (python-flint; reads the pinned `MinimalConstruction/Proofs/critical_moment_core.py`)
- `python3 gen_qf.py`: produces `CoverageStripIdQF.lean` from `qf_template.lean`.
- `python3 gen_zero.py`, then `python3 gen_checks.py zero`: zero-`J` data and moment checks.
- `python3 gen_nonzero.py`: produces `NonzeroData` and `NonzeroDataN`, and pickles `n` to the scratchpad
  (`nz_n.pkl`).
  `gen_nonzero_q.py` needs `nz_n.pkl`, so run `gen_nonzero.py` first, even on a new machine.
- `python3 gen_nonzero_q.py` (`NonzeroDataQ`), then `gen_nonzero_stage.py` (`NonzeroDataH`).
- `python3 gen_nonzero_part.py`: produces `Part`, `DataP0–P4` and `DataPA`, and also writes `DataP1a` and
  `DataPS` into `NoFourMUBs/PRM`.
  - After regenerating, move `DataP1a` and `DataPS` back to `split/` unless you are switching to the split
    version.
- `python3 gen_checks.py nonzero_stage`: produces `CheckH`, `CheckMA`, `CheckMB`, `CheckC`.
- Hand-written files (not generated): Defs, Alg, Fast, Grid, Stage, the CheckS*/CheckQ wrappers, Sum, Zero,
  Nonzero.
- `explore_*.py`, `sim*.py`, `partial*.py`, `rproto.py`, `uni_proto.py` and `count_ops.py` are exploration
  scripts and not needed.
