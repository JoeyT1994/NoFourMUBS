# Exact certificate format and trust boundary

## Two checks with distinct purposes

`python3 verify.py` reconstructs all new targets from definitions, compares the regenerated certificates with the shipped files, and independently replays the integer polynomial circuits. It needs the pinned packages in `requirements.txt` for source regeneration.

`python3 verify.py --circuits-only` uses only the Python standard library. It checks every shipped integer polynomial equality by sparse expansion. This mode verifies the equations in the data; it does not independently reconstruct their connection to the strip definitions or prove the paper's deductions and denominator guards. The full mode supplies that additional source-to-target check.

The reported certificate budget is the sum of the uncompressed JSON files in `certificates/`, including redundant human-inspectable cofactor data as well as integer DAGs. Compressed archive size is not used to claim compliance with the 0.5 MB target.

## Integer polynomial DAGs

The four `*_circuits.json` / `*_dag.json` / `scalar_certificates.json` files have this format:

```text
{
  "format": "integer_polynomial_dag_v1",
  "certificates": [
    {
      "id": "unique descriptive identifier",
      "variables": ["k", ...],
      "nodes": [...],
      "lhs": integer_node_index,
      "rhs": integer_node_index
    }
  ]
}
```

Node indices are zero based. The only operations are:

| Node | Meaning |
|---|---|
| `["const", n]` | Integer constant n, including negative integers |
| `["var", i]` | The i-th variable |
| `["add", i, j]` | Sum of two earlier nodes |
| `["mul", i, j]` | Product of two earlier nodes |
| `["pow", i, n]` | An earlier node raised to a nonnegative integer power |

Every node reference points backward. No division, negative power, floating-point value, radical, external function, or numerical evaluation node is allowed. Rational and Laurent identities are cross-multiplied by their explicit polynomial or monomial denominators before export. The result is an ordinary equality over the integers, hence specializes to the real and complex rings used in the proof.

The standard-library checker evaluates each node as a sparse dictionary from exponent tuples to integer coefficients and requires literal equality of the two resulting polynomials. Source reconstruction separately checks that each target is the intended one. Integer dictionaries are proof computation here, not sample evaluations.

This format has a direct mathematical translation into the repository's `Identity` expression language. The current repository-specific constructors are absent from the handoff, so the return does not invent a compiled adapter. An integrator maps the operations in the table to the actual constructors and proves the source-to-circuit interpretation. The kernel then checks the same denominator-cleared polynomial equalities.

## Files

- `unweighted_circuits.json`: the original determinant/permanent signature, paired lambda equation, universal cubic factorization, moment regrouping, and weighted orthogonality reduction. Factored defining expressions are retained in the DAGs.
- `newton_circuits.json`: the nine actual moment formulas against direct Laurent sums. These use the same function that the boundary checker calls.
- `weighted_boundaries_dag.json`: original nine-moment expressions against their four displayed values plus explicit Gram-relation cofactors; additional denominator factorizations are included when generated by the boundary helper.
- `scalar_certificates.json`: the small scalar factorizations, products of lambda denominators, positivity identities, endpoint evaluations, and rational N2 bounds.
- `unweighted_identities.json` and `newton_identities.json`: compact readable expansions/readouts. These supplement the defining-expression DAGs.
- `full_weighted_certificate.json`: parameters, raw rational expressions, target values, cleared errors, and explicit polynomial quotients for the four curves.

## Boundary cofactor certificates

For each curve, let E be the difference between the original weighted moment and its claimed table value. The exact rational arithmetic writes

```text
E = N / D,        N = m * q.
```

Here m is the numerator of the appropriate Gram relation and q is the explicit supplied polynomial quotient. The defining-expression DAG checks the stronger rational identity after denominator clearing, with the original moment formula on its left. The physical Gram equation sets m to zero; it is never inverted.

The relation is monic in the triangle variable before denominator clearing on the three repeated-modulus branches. On the fourth branch it is

```text
(1+k^2)^2 Y^2 - (9k^4+10k^2+5)Y + 4 = 0.
```

All permitted physical divisions are recorded in REPORT §5. In particular, the special candidate parameters are not discarded by canceling an L at a pole.

## Reproduction and failure behavior

`--regenerate` reconstructs the canonical data; it does not accept old data as an oracle. After intentionally regenerating or editing deliverables, rebuild `SHA256SUMS` before normal replay.

`--self-test` additionally changes a circuit's first target by +1 and requires the independent checker to reject it. This checks a concrete remaining risk: a nominal verifier that reconstructs valid targets but never actually compares the certificate equality.

Python assertions must remain enabled. The entry point explicitly rejects optimized Python execution with assertions disabled.

The exact finite algebra is **CERTIFIED by the returned Python replay**. Its import and replay in Lean are **NOT ESTABLISHED here**. The paper proof does not rely on treating hashes, Python success, or a JSON file as an additional axiom.
